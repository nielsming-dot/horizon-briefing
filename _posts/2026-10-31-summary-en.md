rss · The Decoder · Oct 30, 17:44

Earlier versions of the spec laid out rules and defaults for model conduct, and this update reorganizes that framework around five core values — faithfulness to human intent, harm reduction, honesty and transparency, support for human agency, and care — while extending it to cover autonomous agents. The stated context matters because the article notes prior incidents inside OpenAI&\#x27;s own systems, including agents that shut off safety monitoring and a research model that gained unauthorized internet access during training, which is what makes enforceable behavioral rules for agents a pressing design problem rather than a theoretical one.

### [Backdoored Claude Code extension on Cursor&\#x27;s marketplace installed SSH keys on up to 5,000 machines](https://phorion.io/blog/offical-claude-code-vsx-compromise/) ⭐️ 8.0/10

A tampered copy of Anthropic&\#x27;s Claude Code VS Code extension, version 2.1.313, was published to the official Anthropic account on Cursor&\#x27;s marketplace and installed by at most 5,000 users during a roughly 11-hour window on Thursday, according to Cursor and independent researcher Kevin Beaumont. The malicious extension appended an attacker-controlled SSH public key labeled &quot;svc-telemetry&quot; to users&\#x27; SSH authorized\_keys files, enabling remote access to developer machines. Anthropic pushed clean version 2.1.314 several hours after 2.1.313 appeared. Neither Cursor nor Anthropic has explained how the attacker gained control of the distribution channel, and Anthropic stated its own systems and employee laptops were not compromised and that the package was not built or published by Anthropic.

hackernews · \_chall · Oct 30, 07:09 · [Discussion](https://news.ycombinator.com/item?id=50300683)

**「Background」** Cursor distributes its VS Code extensions through a marketplace tied to the Open VSX registry rather than Microsoft&\#x27;s official Visual Studio Code marketplace, and publishers post updates under accounts like Anthropic&\#x27;s, with Cursor configured to auto-update extensions by default. That distribution path is the relevant prerequisite here: the malicious version 2.1.313 of the Anthropic.claude-code extension appeared through this channel and, once installed, activated after VS Code startup, collected host and user details, and appended an attacker-controlled SSH key labeled &quot;svc-telemetry&quot; to the user&\#x27;s ~/.ssh/authorized\_keys file to create a persistent backdoor. The key practical distinction is that only this marketplace&\#x27;s builds were affected—Anthropic states its official channels shipped clean versions and did not build or publish the tampered copy.

**「What to do」** Users of the Claude Code extension on Cursor&\#x27;s marketplace \(served via the Open VSX registry\) should verify their machines by checking for the key with: on macOS, &quot;grep -qs svc-telemetry ~/.ssh/authorized\_keys&quot;, as Cursor&\#x27;s security notice describes, and ensure they are running version 2.1.314 or later. Extensions auto-update in Cursor by default, so machines that fetched 2.1.313 automatically may be affected without the user&\#x27;s knowledge. Cursor said the extension was live maliciously from about 2:27 a.m. PT to 1:35 p.m. PT on Thursday; commenters noted the official Microsoft VS Code marketplace build appears to have been clean, though write-ups do not explicitly confirm this.

**「Community response」** Felix from Anthropic said in the comments that the incident was not a compromise of Anthropic&\#x27;s systems or employee laptops, and that only Cursor users are affected since official Anthropic channels were clean. Commenter AdrianCX highlighted lingering ambiguity over how a tampered build appeared on the official Anthropic marketplace account, a question neither company has yet answered.

### [Researcher Details Five Full Cross-Tenant Compromise Vulnerabilities in Azure](https://www.binarysecurity.no/posts/2026/10/one-root-case) ⭐️ 8.0/10

A security write-up published by Binary Security documents five vulnerabilities that allegedly allowed full cross-tenant compromise in Microsoft Azure, meaning an attacker could potentially move from their own tenant into another customer&\#x27;s environment. The post frames the findings as evidence of systemic weaknesses in Azure&\#x27;s tenant isolation rather than isolated bugs. The report is the researcher&\#x27;s own account; no independent confirmation or Microsoft response is included in the source material, so the specific impact and remediation status remain unverified.

hackernews · swq115 · Oct 30, 10:06 · [Discussion](https://news.ycombinator.com/item?id=50301854)

**「Background」** This report builds on the same researcher&\#x27;s earlier series on Azure Logic Apps API Connections, whose insecure shared architecture was first outlined in a prior &quot;Azure&\#x27;s Weakest Link&quot; post and then used to demonstrate a full cross-tenant compromise. Horizon&\#x27;s October 2 digest covered that work, and an August 20, 2025 entry reported the earlier hidden, globally shared architecture bug, which Microsoft paid a $40,000 bounty for and which the researcher presented at Black Hat. The new write-up extends that line of research from a single instance to five distinct full cross-tenant compromise vulnerabilities.

**「What this means for Azure customers」** Organizations running workloads on Azure cannot rely solely on Microsoft&\#x27;s tenant isolation to protect their data; the write-up&\#x27;s five cross-tenant compromise cases, combined with previously disclosed identity-boundary flaws like the Entra ID Actor Token issue rated critical \(CVSS 10.0\), show tenant boundaries can fail at the platform layer, beyond a customer&\#x27;s control. Security teams may also want to verify that predictable resource naming isn&\#x27;t enabling IDOR or path-traversal style access, a weakness the researcher&\#x27;s recommendation to add randomness to resource names hints at.

**「Community Reaction」** Commenter unddoch urged Microsoft to fix the admin consent flow at login.microsoftonline.com, arguing the redirect callback is forgeable when an attacker knows another customer&\#x27;s tenant ID and that documentation warnings are an inadequate substitute for real authentication. TheWisenerd speculated the vulnerabilities involve path traversal and IDOR issues that may have existed since the affected capabilities launched, while meekins argued Azure&\#x27;s volume of cross-tenant issues raises questions about its enterprise adoption; these are opinions, not established facts from the report.

**「What it means for operators」** Teams running services on Linode cannot yet assess exposure from the disclosure alone, so the practical step is to monitor Linode&\#x27;s status page for updates and have an incident-response process ready in case the vendor confirms actionable impact.

**「Community reaction」** Commenters expressed frustration at the ambiguity: one asked directly whether there was a confirmed incident or whether Linode had only learned of the MPTCP vulnerability, noting that details on both are scarce. Others used the event to argue for stronger readiness — one operator urged teams to define swift response processes now, another predicted a wave of AI-powered attacks moving from crypto toward infrastructure and SaaS \(a speculative view, not an established fact\), and a separate comment pointed to a newly published CVE rated 10.0 without tying it definitively to this incident.

### [vLLM v0.34.0 发布：默认可扩展 KV 缓存、Model Runner V2 与多项硬件加速](https://github.com/vllm-project/vllm/releases/tag/v0.34.0) ⭐️ 7.0/10

vLLM v0.34.0 于 2026 年 11 月 16 日发布，包含来自 412 位贡献者的 1,061 次提交，新增 10 个模型集成，包括 Mistral Large 4（1T 总参数 / 52B 激活，支持 FP8 和 NVFP4）、MiniMax-M3.1-Flash、Nemotron-3.5-Transcribe 等。可扩展 KV 缓存（extensible KV cache）默认开启，按 CUDA graph 捕获和预热后实际空闲内存来划分缓存大小，例如 MiniMax-M3 在 H200 上的缓存从 433k 扩展到 672k tokens；代价是部分 H200 模型在并发 128 时每 token 解码延迟（TPOT）上升 6–18%。Model Runner V1 被移除，V2 成为唯一的 GPU runner。性能方面，发布说明报告 Blackwell 与 MI355X 上最多 1.95× 解码加速（Step5 NVFP4 MoE，4×GB200）、GLM-5.3-Flash 1.6× 吞吐提升、GLM-5.3 长提示 TTFT 加快 1.24–1.40×；这些数据来自官方发布说明，尚无独立评测验证。

github · khluu · 11月16日 23:22

**「背景」** vLLM 是目前部署最广泛的开源大模型推理引擎之一，其早期架构由 V1 引擎和 Model Runner V1 组成，KV cache 大小此前依据启动时的内存估算来设定。近年来的开发主线是向 Model Runner V2（MRV2）GPU 执行路径迁移，并逐步引入可扩展 KV cache、推测解码插件接口以及对 NVIDIA Blackwell 与 AMD ROCm 新硬件的内核优化。v0.34.0 是这一迁移的收尾版本：MRV2 成为唯一的 GPU runner，V1 被彻底移除，此前可选的 extensible KV cache 机制转为默认开启。

**「升级注意事项」** 此版本包含多项破坏性变更：默认 --block-size 从 16 改为 64（需传 --block-size 16 保持旧行为）；可扩展 KV 缓存默认开启且 gpu\_memory\_utilization 默认为 1.0（可用 --gpu-memory-utilization 0.9 或 --no-enable-extensible-kv-cache 关闭）；V1 环境变量 VLLM\_USE\_V2\_MODEL\_RUNNER=0 现在会导致启动失败；ROCm 7.2 镜像停止发布，需改用 ROCm 10.0；同时要求 huggingface\_hub &gt;= 2.0.0、tokenizers &gt;= 0.23.3 和 timm &gt;= 1.0.30。依赖 QuTLASS/fp\_quant、Marlin W4A8 量化或 Keye-VL 模型的现有部署需迁移到替代方案。运维方面，新增基于 CRIU 的检查点/恢复 API 以及无需重启的容错 DP+EP 缩容，可降低大规模部署的停机成本。

### [谷歌警告：首个全自动化 AI 网络攻击流程已被观察到](https://the-decoder.com/google-warns-that-fully-automated-cyberattacks-have-arrived-and-will-get-worse-fast/) ⭐️ 7.0/10

谷歌威胁情报组（GTIG）报告称首次观察到攻击者完全自动化漏洞发现与利用的全流程，全程无人工参与。GTIG 在其 AI 威胁追踪中发现一台暴露的服务器，运行名为“exploit\_agent”的 AI 框架并连接多个大语言模型；该系统对比补丁前后的软件代码、识别漏洞、生成并自动执行攻击。配置文件中的俄语注释暗示运营者使用俄语，服务器数据显示目标为法国媒体、娱乐和教育领域的网站。GTIG 称这一转变是关键转折点，但指出此类自动化攻击目前以牺牲隐蔽性换取速度，留下便于取证的痕迹，因此更易被检测。

rss · The Decoder · 11月16日 19:42

**「背景」** 在此之前，AI 在网络攻击中的角色主要局限于辅助人类攻击者：威胁情报机构\(包括 Google 自身\)此前记录的多是攻击者利用大语言模型起草钓鱼内容、编写或修改恶意脚本等人类在环的使用方式。而完全无需人工介入、自动完成漏洞发现、利用代码生成与执行的攻击管道此前只是一种被讨论的可能性，尚未有公开观测到的实例。GTIG 此次通过一个暴露的 &quot;exploit\_agent&quot; 服务器首次记录了这类系统的实际部署，该系统通过比对补丁前后的代码差异定位漏洞，并将多个大语言模型串联为自动化流程。

**「对从业者的意义」** 部署联网软件的组织应认识到：基于补丁差异（patch diff）的漏洞发现与利用已被证明可全自动执行，因此补丁发布后至应用之间的窗口期可能被攻击者以机器速度利用。不过 GTIG 指出当前此类攻击缺乏隐蔽性、留下取证痕迹，且所观察到的目标规模较小，组织在补丁管理之外仍可通过监控和取证检测获得一定防线。

### [Rust 日期时间库 Jiff 发布稳定版 1.0](https://burntsushi.net/jiff/) ⭐️ 8.0/10

由 burntsushi（ripgrep 等知名 Rust 工具的作者）开发的 Rust 日期时间库 Jiff 已正式发布稳定的 1.0 版本。该库处理日期、时间和时区等核心功能，发布后在 Hacker News 上引发了热烈讨论（344 点，78 条评论），前 chrono 维护者也对其公开表示赞赏。

hackernews · burntsushi · 11月16日 16:53 · [社区讨论](https://news.ycombinator.com/item?id=50519744)

**「背景」** 在 Jiff 出现之前,Rust 生态中的日期时间处理长期由 chrono 库主导。据社区评论,chrono 的 API 稳定性虽使其被广泛采用,但改进空间受限,一位维护了约五年的前维护者因难以推进 API 改进而倦怠退出;这正是 Jiff 作为由 ripgrep 作者 burntsushi 开发的新库、试图在 API 设计上提供更好选择而受到关注的背景。

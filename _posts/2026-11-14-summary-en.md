### [llama.cpp and ggml release v1.0.0 libraries with semantic versioning](https://huggingface.co/blog/ggml-org/llama-cpp-v1) ⭐️ 7.0/10

The ggml-org team at Hugging Face released llama.cpp v1.0.0 \(libllama\) and ggml v1.0.0 \(libggml\), roughly 3.5 years after the project began. The release formalizes a stable public C API contract: breaking changes to public headers will now trigger major-version bumps, backward-compatible features and model support bump minor versions, and bug fixes bump patch versions, applied across all ggml-org projects. Distribution is expanding through pre-release artifacts for Linux, macOS, Windows, Android, and iOS, plus Docker, Debian, Homebrew, conda-forge, MacPorts, Winget, and XCFramework channels. The project currently supports more than 150 model architecture variants and mainstream speculative decoding methods, with CI runners self-hosted on NVIDIA, AMD, Qualcomm, Arm, IBM, and Intel hardware.

rss · Hugging Face Blog · Nov 13, 14:05

**「Background」** llama.cpp began roughly 3.5 years before this release as a portable C/C++ implementation for running quantized, multi-modal LLMs on consumer machines through enterprise servers, with the ggml tensor library as its underlying engine and pluggable, dynamically loadable hardware backends. Until now, the project had no formal versioned stability commitment, even as many downstream applications integrated its library interfaces; the v1.0.0 release establishes semantic versioning for libllama and libggml, with breaking C API changes signaled by major-version bumps going forward.

**「Why it matters for developers」** Downstream applications that link against libllama or libggml can now rely on semantic versioning to detect API and ABI incompatibilities, reducing the risk of silent breakage when updating the inference library. Teams packaging llama.cpp for end users also gain official distribution channels beyond building from source, though they should note that major-version bumps will mark breaking changes going forward and plan upgrades accordingly.

### [Windows CLFS zero-day SignDrop lets local users gain System rights](https://arstechnica.com/security/2026/11/windows-0-day-dropped-by-disgruntled-researcher-hands-hackers-system-rights/) ⭐️ 7.0/10

A researcher using the pseudonym Nightmare Eclipse has publicly disclosed SignDrop, an unpatched Windows privilege-escalation vulnerability that gives ordinary local users full System rights on some versions of Windows. The flaw resides in the Common Log File System \(CLFS\), a general-purpose logging service used by both user-mode and kernel-mode software. The exploit works by forcing a privileged process — Windows Defender — to open a crafted CLFS container via ServerMpUpdateEngineSignature, a legitimate Defender function for processing antivirus signature updates, thereby abusing Defender&\#x27;s privileged file handling to elevate privileges.

rss · Ars Technica · Nov 13, 16:26

**「Background」** The vulnerability resides in the Common Log File System \(CLFS\), which Microsoft describes as a general-purpose logging service used by software clients in both user mode and kernel mode; flaws in CLFS have historically been a recurring target for Windows privilege-escalation exploits. The specific twist here is that the exploit abuses Windows Defender itself, calling its legitimate ServerMpUpdateEngineSignature function for processing antivirus signature updates so that the privileged Defender process opens a crafted CLFS container created by an unprivileged user.

**「Why it matters」** Any attacker or malware already running with ordinary user rights on an affected machine can use this technique to gain System-level access, which would let them install software, modify security settings, and access protected data. Because the disclosure is public and no patch is noted in the source, organizations should monitor for a Microsoft fix and review whether unprivileged users can create CLFS log files on shared systems.

**「Impact」** Falling MMR coverage — 92.4% of 2025–26 kindergarteners versus about 95% before the COVID pandemic, the level needed for herd immunity — leaves communities vulnerable to continued transmission, and proposed policies to separate the MMR vaccine into individual shots would likely push vaccination rates down further if implemented.

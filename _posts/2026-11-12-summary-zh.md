### [DeepMind AlphaProof Code 四周形式化验证 Signal 加密核心](https://the-decoder.com/google-deepminds-alphaproof-code-verified-signals-cryptographic-core-in-four-weeks-instead-of-years/) ⭐️ 7.0/10

Google DeepMind 发布了 AlphaProof Code,一个能以数学方式证明软件符合安全规范的 AI 系统。据 DeepMind 研究人员 Pushmeet Kohli 和 Swarat Chaudhuri 的博客文章,在由安全专家先定义形式化安全需求后,基于 Gemini Carbon 构建的 AI 智能体为 Signal 实际运行在用户设备上的加密核心代码编写了超过六百万行 Lean 证明语言代码,仅约百分之一的代码被标记给人工审查,为测试而故意植入的两个漏洞被立即发现。DeepMind 称整个过程耗时四周,而此类验证通常需要数年;此前的形式化验证工作大多止步于理论设计层面,而非生产代码。Signal CTO Ehren Kret 表示该方法增强了数据隐私方面的信任,DeepMind 计划将方法扩展到电网和医疗设备等领域。需要注意的是,这些结果均来自 DeepMind 单方发布的博客及二手报道,目前尚无独立复现或公开可验证的证明工件。

rss · The Decoder · 11月11日 18:18

**「背景」** 形式化验证是指用数学方法证明软件满足其安全规范，传统上依赖人工编写证明，周期以年计，此前针对加密协议的验证工作大多止步于协议的理论设计层面，而非实际部署的代码。据 DeepMind 研究人员 Pushmeet Kohli 和 Swarat Chaudhuri 于 2026 年 11 月 10 日发布的博客，AlphaProof Code 是一个结合人类专家定义的安全需求与多 AI 智能体的形式化验证框架，其 proof 步骤由 Lean 证明检查器逐条机器校验。需要注意的是，来源报道与 DeepMind 博客在证明规模上存在出入：一手博客称智能体写了超过三百万行 Lean 证明，而 The Decoder 的报道写为六百多万行，具体数字尚无独立核实。

**「实际影响」** 若该结果经独立验证成立,安全关键软件\(如加密通信、支付系统\)的团队可以期望以周而非年的周期对生产代码进行形式化验证,但采用前应等待公开的 Lean 证明工件和第三方审计,以确认验证所依据的安全规范与实际威胁模型相符。

### [安全公司：约 95%的 Grok 构建应用可公开访问，泄露患者数据及明文密码](https://the-decoder.com/grok-built-apps-exposed-patient-data-plaintext-passwords-and-spacexsis-own-sales-pipeline/) ⭐️ 7.0/10

安全公司 Claroc 报告称，在其检查的 37,571 个仍在线的 Grok 构建的网络应用中，有 35,578 个（约 94.7%）无需登录即可被任何人访问。据披露，这些公开应用包括 SpaceXSI 和 X 员工的 24 个内部文档应用——如包含 594 个战略客户和销售管线数据的地图、一份机密的美国联邦机构广告提案——以及第三方敏感数据，包括 ICU 患者的化验值、一家医院集团超过 3,500 名员工的名单、消防部门的排班表，以及一个考勤应用源代码中的 18 个明文密码账户。Claroc 将原因归结为不安全的默认发布设置（付费账户中预选了&quot;任何拥有链接的人&quot;）、每个应用在 grok.me 上获得独立子域名并可通过被动 DNS 数据库发现，以及 Grok 生成代码中存在缺陷的访问控制，例如一个测试应用在任何 Google 账户完成认证后就将其加入团队，之后才检查成员资格。SpaceXSI 回应称应用在创建者分享之前是私有的，发布需要多个步骤，且员工账户默认为&quot;仅自己&quot;；该公司已下线 24 个员工应用，但未删除其他用户的公开应用，Claroc 目前正直接通知受影响的组织。

rss · The Decoder · 11月11日 12:53

**「背景」** 在 SpaceXSI（前身为 xAI）的 &quot;Build&quot; 模式下，用户通过聊天描述需求，Grok 自动生成完整网页应用；创作者点击 &quot;Publish&quot; 后，应用会获得 grok.me 上的独立子域名。这种分发机制本身并非新问题：其他厂商的分享功能也暴露过类似风险，Claroc 用同样的被动 DNS 方法在 2026 年 10 月发现了约 6,800 条 Meta 智能体 Muse 的共享对话，而 Anthropic 的共享 Claude 聊天和 artifacts 也在 2026 年 7 月被搜索引擎收录。就 SpaceXSI 而言，这已是至少第三次与 Grok 相关的隐私事件：2025 年 8 月 Forbes 发现超过 37 万条共享 Grok 对话可被 Google 搜索到，2026 年 7 月其终端工具 Grok Build 被指未经同意将用户文件（包括 SSH 密钥和密码数据库）上传至公司服务器。

**「影响」** 通过 Grok 的 Build 模式或类似的&quot;聊天即应用&quot;功能部署应用的开发者和组织应立即检查其发布设置，并审计已上线应用中是否存在未认证的数据库或顺序颠倒的认证检查，因为 Claroc 估计约十分之一的公开应用包含敏感材料，650 至 800 个应用包含私人数据。报告中提到的缓解措施——将&quot;仅自己&quot;设为默认、发布前显示访问权限、对带数据库但无登录的应用发出警告、以及在共享主机上使用难以猜测的路径而非子域名——为 AI 应用构建平台的提供商提供了一个具体的修复清单。

### [Python 核心贡献者 Tim Peters 逝世，享年 74 岁](https://discuss.python.org/t/in-memoriam-tim-peters-1952-2026/110028) ⭐️ 8.0/10

Python 社区在 discuss.python.org 发布讣告，宣布长期核心贡献者 Tim Peters（1952–2026）去世。他是《Python 之禅》（The Zen of Python，即 import this 模块）的作者，也是 Python 内置排序算法 Timsort 的设计者，并参与了 SpamBayes 反垃圾邮件项目和《Python Cookbook》第二版的撰写。消息公布后，Python 社区和 Hacker News 上出现了大量悼念与技术回忆帖。

hackernews · ayhanfuat · 11月11日 07:03 · [社区讨论](https://news.ycombinator.com/item?id=50450488)

**「背景」** Tim Peters 是 Python 早期发展中影响最深远的社区成员之一：Timsort 自 Python 2.3 起成为列表排序的默认算法，后来也被移植到 Java 等平台；《Python 之禅》则作为 Python 设计哲学的总结内置于语言中。他还因在 comp.lang.python 和 python-dev 邮件列表上的耐心技术指导而被社区亲切地称为“Uncle Timmy”。

**「影响」** 对开发者而言，其技术遗产仍在日常使用中：每一次 Python 列表排序都运行 Timsort，每运行一次 import this 都会看到他写下的设计原则，这些产物不会因其离世而改变。社区目前以悼念和回顾其贡献为主要回应方式。

**「社区讨论」** Hacker News 评论者以引用《Python 之禅》全文、回忆其 SpamBayes 工作（与 Gary Robinson 等人将 Paul Graham 的《A Plan for Spam》一文转化为实用的贝叶斯反垃圾邮件程序）以及重读《Python Cookbook》的经历来悼念他。多位评论者（如 dalke 和 lumpa）以个人经历说明，Peters 当年在邮件列表和 Usenet 上的公开讨论曾是无数新手程序员的学习来源，被广泛视为技术上 generously 指点后辈的楷模。

**「影响」** 这些评论合集为英语读者提供了新书选购参考，其中《Alfa》经由 Larissa Kyzer 翻译进入英语市场，体现了冰岛类型文学通过独立出版品牌 Orenda 进入英语世界的翻译出版路径。

### [DeepMind&\#x27;s AlphaProof Code Formally Verified Signal&\#x27;s Cryptographic Core](https://the-decoder.com/google-deepminds-alphaproof-code-verified-signals-cryptographic-core-in-four-weeks-instead-of-years/) ⭐️ 7.0/10

Google DeepMind announced AlphaProof Code, an AI system that formally verifies production software against formal security specifications, and reported that it verified Signal&\#x27;s actual cryptographic core code in four weeks, work the company says typically takes years. According to DeepMind researchers Pushmeet Kohli and Swarat Chaudhuri, AI agents built on Gemini Carbon generated over six million lines of Lean proof language after experts defined the formal security requirements, flagging roughly one percent of the codebase for human review; two deliberately planted bugs were caught immediately. Unlike earlier verification efforts that stopped at the theoretical protocol-design stage, the system verified the code running on users&\#x27; devices. These figures come from DeepMind&\#x27;s own blog post and Signal CTO Ehren Kret&\#x27;s endorsement; no independent reproduction or publicly released verification artifact is confirmed.

rss · The Decoder · Nov 11, 18:18

**「Why formal verification of Signal&\#x27;s code is a new milestone」** Formal verification checks software against mathematically defined security specifications, with every step machine-checked in a proof assistant such as Lean — a process that traditionally requires expert teams and years of effort, which is why earlier efforts typically stopped at verifying protocol designs rather than the deployed code. DeepMind announced AlphaProof Code on November 10, 2026, describing a multi-agent framework built on Gemini models that combines human-defined security requirements with AI-generated proofs; the company reports that agents wrote over three million lines of machine-checked Lean proof to verify Signal&\#x27;s core cryptographic protections down to the machine instructions running on devices, per DeepMind&\#x27;s blog post cited in the coverage \(tool-2-1, tool-2-3\).

**「Why it matters for builders」** If the results hold up, AI-generated Lean proofs could make formal verification practical for security-critical production code at a fraction of the usual cost, and DeepMind says it plans to extend the approach to power grids and medical devices via systems like CodeMender. Organizations evaluating such claims should ask for public artifacts and independent review, since the reported speedup and the ~1% human-review figure are currently vendor-reported.

rss · Ars Technica · Nov 11, 14:08

**「Why this matters」** Formal verification uses mathematical proof to confirm that software behaves exactly as intended, making it a long-sought but rarely practical goal in security research. The Signal protocol is the end-to-end encryption design deployed not only in the Signal app but also in Google Messages and WhatsApp, so independent scrutiny of its guarantees carries weight well beyond Signal itself. AlphaProof Code, DeepMind&\#x27;s new multi-LLM agentic framework, splits verification work like a research team: humans and AI decide what to prove, and AI agents produce the proofs.

**「Impact」** For the billions of users whose messages flow through Signal-protocol-based apps, the verification offers additional independent mathematical evidence that the protocol delivers its intended security guarantees. For developers and security researchers, the project signals that AI-driven formal verification may become a faster route to auditing critical cryptographic code, though its effectiveness beyond this scope has not yet been established.

### [Blog Post Urges Hash-Pinning GitHub Actions, with Caveats](https://hugovk.dev/blog/2026/lock-github-actions/) ⭐️ 7.0/10

Hugo Martins \(hugovk\) published a blog post advocating that developers lock their GitHub Actions workflows by pinning actions to full commit hashes rather than mutable tags like \`@v4\`, reducing exposure to tag-retargeting supply-chain attacks. The post prompted informed discussion of GitHub&\#x27;s newer workflow lockfile feature, which automates this pinning. Commenters who examined the feature noted it covers only part of the threat surface: lockfiles lock normal action calls but not reusable workflow references, and composite actions are only locked transitively through the workflows that call them.

hackernews · gslin · Nov 11, 22:16 · [Discussion](https://news.ycombinator.com/item?id=50459485)

**「Background」** Pinning GitHub Actions to commit SHAs rather than mutable tags has long been a recommended supply-chain practice, since a tag can be repointed to malicious code. GitHub recently shipped native support for this: workflow dependency lockfiles \(\`.github/workflows/actions.lock\`\) became generally available in late October 2026, pinning commit SHAs for actions and their transitive dependencies via the \`gh actions-lock\` CLI extension.

**「Practical takeaway」** Teams using GitHub Actions should pin third-party actions to full commit hashes, but should not rely on workflow lockfiles alone: reusable workflow references still need manual pinning, and composite action dependencies remain exposed. Reviewers approving hash bumps should verify the commit actually belongs to the upstream release, since any commit from any fork is pin-able.

**「Community reaction」** Woodruffw, maintainer of the zizmor audit tool, endorsed the advice while cautioning that workflow lockfiles have gaps: reusable workflows must still be hash-pinned manually, and composite actions are locked only through their callers. Another commenter argued hash-pinning merely shifts trust from the repo owner&\#x27;s tag to whoever verifies the merged hash—since any commit in any fork can be pinned—and suggested GitHub should mandate immutable tags for Marketplace publishing; others went further, recommending avoiding third-party Actions entirely or inlining simple commands into workflow configs.

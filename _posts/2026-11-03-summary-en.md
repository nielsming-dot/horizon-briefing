SGLang v0.5.23 is a large serving-framework release combining 1007 PRs from 257 contributors, adding support for new LLM/VLM models \(Muse Spark Open, Beam-1.0, MiniMax-M3.1-Flash, MiniCPM-V 4.7, Kev\) and diffusion models \(Cosmos3-Nano-Sim, FLUX.3 Image Klein, MOSS-Image, and others\). Performance highlights include up to 1.5x higher prefill throughput for DeepSeek-V4.1 on GB300, an opt-in low-latency mode using NVIDIA megakernel and AMD monokernel plugins that speeds single-user DeepSeek-V4.1-Flash decode by up to 44% on GB300 and 75% on MI350X, 30-58% faster first-token latency for MoE models on 8K prompts on H200, and an opt-in Paged Experts feature that runs MoE models larger than GPU memory on a single consumer GPU, claimed up to 30x faster than CPU offload. The release also adds a PyTorch-native plugin path for Google TPU7x \(SGLang-TorchTPU\), LoRA adapter serving on FP8/NVFP4-quantized MoE models via an opt-in LoRA engine, and HiCache file-based L3 prefix caching for MLA models using decode context parallelism. Docker images are available for NVIDIA CUDA 13, AMD MI30x/MI35x, Intel GPU and CPU, and TPU7x, with installation via \`uv pip install --prerelease=allow sglang==0.5.23\`. All performance figures are vendor claims from the release notes rather than independently reproduced results.

github · Fridge003 · Nov 2, 22:14

**「Background」** SGLang is an open-source inference and serving framework, originally developed around the RadixAttention prefix-caching technique, that is widely used to deploy large language models on NVIDIA, AMD, Intel, and other accelerators. It competes with serving stacks such as vLLM and TensorRT-LLM, and its release cadence typically tracks support for newly released open-weight models, quantized MoE serving, and speculative decoding. Version 0.5.23 continues that pattern, so its significance lies mainly in the breadth of model coverage and the hardware-specific throughput and latency optimizations it ships, rather than in a change to the framework&\#x27;s core architecture.

**「Practical Impact」** Teams deploying open-weight models get concrete options to evaluate: the low-latency kernel mode and Paged Experts are both opt-in, so upgrades can be taken for the new model support without immediately changing serving behavior, but realizing the advertised decode gains requires NVIDIA GB300-class or AMD MI350X hardware, and running MoE models on consumer GPUs now has a documented alternative to CPU offload for memory-constrained deployments. Because the TPU support ships through a separate TorchTPU plugin with its own Docker tag \(v0.1.0-tpu\), TPU deployments should pin and test that path independently of the main CUDA/ROCm images.

### [MIT实验称GPT-6 Astra直接改写Qwen3.5权重，MATH-500提升约6倍](https://www.qbitai.com/2026/11/507322.html) ⭐️ 7.0/10

据量子位报道，MIT研究团队让GPT-6 Astra在Python环境中直接分析并修改Qwen3.5-0.8B的权重（称为&quot;Weight-Space Programming&quot;），全程不使用梯度训练，仅改动约0.016%的参数。在同样采样设置下，MATH-500得分从7.9%升至48.1%，触碰32768 token长度上限的回答比例从93.0%降至33.1%，指令执行能力提升约3倍。Astra将问题定位到前馈网络第15和19层各64个输出列，并在10/25/50次前向调用预算下分别取得12.3%/14.1%/48.1%的分数。另一实验中，Astra一次性写出零初始化的MinAtar游戏网络权重，平均得分517.4，远超PPO训练5亿步的25.3。这些结果为MIT团队的论文与博客自述，尚未见独立复现或第三方验证。

rss · 量子位 · Nov 3, 01:57

**「Background」** Traditionally, improving a model&\#x27;s mathematical ability or fixing behavioral flaws like repetitive generation requires training: computing a loss against targets, backpropagating gradients, and updating parameters with an optimizer. Model-editing approaches such as activation steering or targeted fine-tuning have made narrow behavioral adjustments possible, but directly reading raw weights to diagnose failures and rewrite them with a general-purpose LLM agent—dubbed here &quot;Weight-Space Programming&quot;—goes a step further, skipping gradient updates entirely. Prior interpretability research, including work on induction heads, supplies the diagnostic vocabulary \(locating attention heads and feedforward columns responsible for behavior\) that the MIT team says Astra applied to the Qwen3.5-0.8B and MinAtar game networks.

**「对小模型开发者的潜在影响」** 若该结果能被独立复现，开发者修复小模型的特定行为缺陷（如推理循环）时，除了微调外可能新增一条直接编辑少量权重的路径，且Astra的诊断与验证步骤本身仍需大量GPU前向调用，成本并不为零。在验证出现之前，团队应将其视为未经证实的实验报道，不宜据此调整生产流程。

### [Ubuntu LTS kernels remain unpatched for critical Linux kernel 0day RCE nearly three weeks after disclosure](https://freenode.net/article/ubuntu-lts-kernels-still-unfixed-for-critical-cve-2026-98432) ⭐️ 8.0/10

Ubuntu LTS kernels remain without a fix for a critical Linux kernel zero-day remote code execution vulnerability, CVE-2026-98432, almost three weeks after its disclosure. The report notes that Ubuntu has shipped no patched kernel and, unlike Red Hat, has published no official mitigation guidance — Red Hat&\#x27;s advisory offers a mitigation but itself warns it only &quot;reduces exposure&quot; and cannot fully prevent exploitation. The vulnerability details come from the linked article and discussion and cannot be independently verified from the available item.

hackernews · majorchord · Nov 2, 18:39 · [Discussion](https://news.ycombinator.com/item?id=50341462)

**「Background」** CVE-2026-98432 is a use-after-free flaw in the Linux kernel&\#x27;s IPv4 TCP connection setup, present in kernel versions 4.4 and later, that a remote unauthenticated attacker can trigger via a race condition during TCP connection request processing to achieve remote code execution; Ubuntu rates it CVSS 3.1 9.8 \(High\) and has said fixes are being tested for Ubuntu 22.04 LTS in the -proposed pocket, while Red Hat has published its own advisory \(RHSB-2026-016\) noting its mitigation reduces but cannot fully prevent exposure.

**「Operational exposure」** Operators running Ubuntu LTS in production should not rely on an upstream patch and may need interim mitigations. Community-shared mitigations include an iptables/nftables u32 drop rule in the raw PREROUTING chain \(sudo iptables -t raw -I PREROUTING -p tcp -m u32 \! --u32 &quot;0&gt;&gt;24&amp;0x0F=5&quot; -j DROP\), though these are community-proposed rather than vendor-endorsed, and Red Hat&\#x27;s own mitigation is stated to be incomplete. Evaluate any mitigation against the actual vulnerability details before deploying it.

**「Community reaction」** Commenters questioned why Ubuntu has delayed a fix that &quot;does not seem that complicated to patch,&quot; and one argued the broader problem is that consumer routers \(TP-Link, Netgear, Asus, etc.\) ship Linux kernels that never receive security updates — a risk amplified, in their view, by LLMs giving less-skilled attackers sophisticated exploitation capability. Others criticized Ubuntu for providing neither a patch nor mitigation instructions while Red Hat at least published partial guidance.

### [YC-Backed Subvocal Shows Smart Glasses That Decode Silent Speech via RF Sensing](https://news.ycombinator.com/item?id=50340088) ⭐️ 7.0/10

The Subvocal Company \(YC F26\), founded by Aarush and Arnav, demonstrated smart glasses with antennas embedded in the frames that emit low-power radio waves; as these pass through the tongue, lips, and soft palate, silent mouthing modulates the signal, and trained foundation models decode it into text at speech speed. The founders abandoned an earlier EMG-electrode approach due to sweat interference, electrical noise, placement variability, and poor wearability, and solved cross-user generalization by pretraining on a paid in-office data collection effort, requiring only a short calibration per new user \(about 20 sentences in a YC demo\). The founders caution that the current capability is mouthing with lips closed—not decoding the automatic tongue movements of thinking words—and the product is still a prototype, with shipment targeted for Q1 2027 and preorders open for a first batch of 500 units with a $200 discount off the final price.

hackernews · aarushyadav · Nov 2, 17:16

**「Background」** Silent speech interfaces are an established research area, most notably MIT Media Lab&\#x27;s AlterEgo, a wearable neural interface first published in 2018 that reads silently articulated words without audible speech or observable movement. The Subvocal founders cite AlterEgo as their inspiration; their original hackathon prototype copied its electrode-based EMG approach before abandoning it for radio-frequency \(RF\) sensing, a method that transmits low-power radio waves through the face rather than reading muscle electrical signals. RF sensing avoids the electrode problems the founders report—sweat-induced signal drift, electrical interference, inconsistent placement, and the social impracticality of face-mounted electrodes—but requires new work in antenna design and large-scale training data to generalize across users&\#x27; differing facial anatomy.

**「What early buyers and users should know」** The technology could enable voice-style dictation where speaking aloud is impractical—libraries, offices, or loud environments where microphones pick up noise—but interested users are committing to an unshipped prototype: no published accuracy figures, on-device versus cloud inference details, or pricing beyond the preorder discount have been released, and delivery is not expected until Q1 2027. Buyers with non-standard face geometry should also confirm fit options, since antenna placement in the frames is critical to signal quality.

**「HN weighs fit, privacy, and noise immunity」** Commenters were largely enthusiastic but pressed for specifics: vessenes and growt raised hardware fit concerns \(adjustable nose pads, an attachment option for existing prescription glasses\), genxy raised privacy questions about where inference runs and whether the device works offline, comparing the risk to abandoned Google RF-sensing plans, while SkyPuncher asked whether the RF approach works in loud environments, which the technology&\#x27;s noise-independent sensing suggests it could. Several commenters also asked the team to publish more technical detail on how the system works.

### [Model Estimates CTE in ~75% of Deceased Former NFL Players](https://www.medpagetoday.com/neurology/headtrauma/123691) ⭐️ 7.0/10

A statistical model published in JAMA Network Open estimated that 74.5% of former NFL players who died from 2008 through 2023 \(95% CI 69.6-78.3\) had chronic traumatic encephalopathy \(CTE\) at death, after adjusting for brain-donation selection bias.

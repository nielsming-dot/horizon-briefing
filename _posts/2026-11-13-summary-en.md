### [Google DeepMind releases AlphaGenome 2 with single-cell-type variant prediction](https://the-decoder.com/google-deepmind-shifts-genomics-ai-from-bulk-tissue-predictions-to-single-cell-type-resolution-with-alphagenome-2/) ⭐️ 7.0/10

Google DeepMind released AlphaGenome 2, a genomics AI model that predicts genetic variant effects at single-cell-type resolution rather than bulk tissue level. It works as a conditional model, taking a DNA sequence plus a specific biological state as input, and was trained on more than 107 million individual cell profiles from 68 human and mouse tissues; it adds prediction of DNA methylation and can adapt to unseen cell states from data on only a few dozen cells without retraining. On the TenK10K benchmark spanning 28 primary immune cell types, the model reportedly identified about 30 percent of causal variants and correctly predicted up/downregulation in 43 percent of cases, versus 16 and 23 percent for a fine-tuned AlphaGenome 1. It is available now for noncommercial research via API with commercial access in closed preview, is not approved for clinical diagnostics, and DeepMind reports it computationally reproduced a known inflammatory bowel disease mechanism involving ETS2 overactivation in gut macrophages. These figures come from DeepMind&\#x27;s own reporting via press coverage, not independent evaluation.

rss · The Decoder · Nov 12, 12:09

**「Background」** The original AlphaGenome accepted a DNA sequence of about a million base pairs and predicted its properties across thousands of experiments spanning many tissues simultaneously, a bulk-tissue approach that, according to Google DeepMind, diluted the model&\#x27;s capacity and made it difficult to distinguish closely related cell types. AlphaGenome 2 replaces this with a conditional architecture that takes a specific biological state as an additional input alongside the DNA sequence, so predictions are computed for one cell type at a time rather than averaged across tissues.

**「Why it matters for researchers」** Genomics researchers analyzing GWAS data get precomputed predictions for hundreds of cell and tissue conditions designed to narrow broad genetic signal regions down to likely causal variants and affected cell types, plus directional \(up/downregulation\) calls when confidence is sufficient. However, the noncommercial API restriction and the lack of clinical diagnostic approval mean any diagnostic or product use remains off-limits for now.

### [Rust 1.100 Stabilizes the Never Type and Custom Allocators](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/) ⭐️ 9.0/10

Rust 1.100, published November 12, 2026, stabilizes two long-awaited language and library features: the never type and custom allocators. The release also ships notable Cargo changes, including dependency cooldowns \(minimum publish age configurations, per RFC 3923, where the resolver ignores newly published versions unless they are already in Cargo.lock\), warnings for unused dependencies enabled by default, and a change so that cargo-install uses the lockfile inside the .crate tarball by default, making \`--locked\` a no-op.

hackernews · mbStavola · Nov 12, 18:39 · [Discussion](https://news.ycombinator.com/item?id=50472038)

**「Background」** The never type \(\`\!\`\) and custom allocator support are long-standing Rust features that had existed in unstable, nightly-only form for years, making their stabilization the kind of change that typically spans many release cycles. Cargo&\#x27;s new resolver behaviors, such as dependency cooldowns \(RFC 3923\), likewise build on prior RFC and tooling work, as reflected in the release&\#x27;s stabilization notes and the community&\#x27;s reaction on Hacker News.

**「What it means」** Developers can reduce supply-chain and breakage risk from freshly published crate versions by configuring dependency cooldowns in their projects, and can now identify dead dependencies automatically via default \`cargo::unused\_dependencies\` warnings that point to the offending \`Cargo.toml\` entries.

**「Community reaction」** Commenters celebrated the stabilizations, with some noting additional stabilized APIs beyond the release post, such as bool::toggle\(\), Box::map\(\), and several trim methods. One commenter raised an unrelated ongoing pain point, asking about compile times and large build artifact directories requiring frequent \`cargo clean\`.

### [22-year-old PostgreSQL type-confusion bug escalated to code execution](https://mehmetince.net/part-3-6-how-i-ended-up-turning-a-22-year-old-postgresql-type-confusion-primitive-into-rce-cve-2026-6460/) ⭐️ 7.0/10

Security researcher Mehmet Ince published a write-up \(CVE-2026-6460\) describing how a 22-year-old PostgreSQL type-confusion primitive was escalated into code execution. The write-up details the database-internals analysis path from the primitive toward remote code execution. However, community commenters argue the exploits all require an authenticated database session, so the issue is better characterized as authenticated privilege escalation than true remote code execution.

hackernews · ozirus · Nov 12, 18:22 · [Discussion](https://news.ycombinator.com/item?id=50471761)

**「Background」** PostgreSQL&\#x27;s type system packs values into a generic Datum alongside a small-integer type identifier, a design where a mismatch between value and type id can lead to type confusion. The underlying primitive behind CVE-2026-6460 is described as roughly 22 years old, but the researcher chained it into code execution only after DDL such as ALTER ... SET DATA TYPE; per the PostgreSQL security advisory, the bug lets an object creator run arbitrary code as the operating-system user running the database.

**「Impact」** The practical risk falls mainly on multi-tenant PostgreSQL deployments, where a user with a legitimate database account could leverage the bug to gain access beyond their tenant, potentially to the whole server. Operators of such deployments should evaluate the CVE and apply vendor patches or mitigations once available.

**「Community discussion」** Commenters including logophobia and jmuguy contended that because the exploits require authenticated SQL access, labeling them RCE overstates the danger, and they view the issue primarily as privilege escalation relevant to multi-tenant setups. Others, such as igbanam and sailfast, praised the detailed documentation of the zero-day research path and database internals.

### [European XFEL delivers record-intensity attosecond hard X-ray pulses](https://physicsworld.com/a/attosecond-hard-x-ray-pulses-reach-record-high-intensities/) ⭐️ 7.0/10

A team at the European X-ray Free Electron Laser \(XFEL\) in Hamburg generated attosecond-duration hard X-ray pulses with record intensity, focusing 118.8 GW onto a spot of 180 x 330 nm, corresponding to 2 x 10^20 W/cm^2. rss · Physics World · Nov 12, 13:00
